# D1.1 — Trait `StackDetector` + реестр модулей

**Фаза:** D1  
**Зависимости:** M2.2 detect modules (существующие)  
**Параллельность:** Dev + Test

---

## 1. Цель

Формализовать «один язык / экосистема ≈ один модуль» без смены поведения PriorityTable.

```rust
pub trait StackDetector: Send + Sync {
    fn id(&self) -> &'static str;
    /// path = candidate/project root; markers from scan
    fn detect(
        &self,
        path: &Path,
        markers: &[MarkerHit],
    ) -> Result<Vec<Detection>, Error>;
}

/// Stable order registry (ecosystem modules).
pub fn detector_registry() -> &'static [&'static dyn StackDetector];
```

Сохранить текущие `detect/*` модули; registry явный (не ad-hoc match в одном файле).

---

## 2. Модульность

```text
src/detect/
  mod.rs              # registry(), re-exports
  traits.rs           # StackDetector
  # existing per-ecosystem modules stay
  rust.rs | node.rs | python.rs | …
```

Не плоский `detect/frameworks/` (Next без Node-контекста бессмысленен) — frameworks внутри экосистемы (follow-up M2.2).

## 3. Поведение

- PriorityTable path вызывает те же детекторы, merge policy **как сейчас** (language priority, frameworks union).
- Пустые markers → probe all detectors (уже принято) — не менять без решения.
