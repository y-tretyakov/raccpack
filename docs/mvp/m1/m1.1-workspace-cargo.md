# M1.1 — Workspace Cargo: `raccpack-core`, пустой `raccpack-cli`, общая лицензия/README

**Фаза:** M1 — Каркас workspace и core  
**Веха:** MVP → 0.1.0  
**Статус этапа:** todo  
**Зависимости:** нет (первый этап)  
**Параллельность:** test: n/a (scaffolding / design + structure)

---

## 1. Цель этапа

Создать **минимальный, компилируемый Cargo workspace**, в котором:

- есть library-crate `raccpack-core` (будущее ядро бизнес-логики);
- есть binary-crate `raccpack-cli` (пока пустой/заглушка);
- зафиксированы лицензия, корневой README и базовые соглашения по структуре репозитория;
- workspace собирается одной командой `cargo build` / `cargo test` без ошибок.

Этап **не** реализует domain, config, scan или facade. Только каркас.

---

## 2. Контекст из архитектуры

Из [raccpack-architecture-vision.md](raccpack-architecture-vision.md) §7:

```text
raccpack/
  Cargo.toml                 # workspace
  crates/
    raccpack-core/           # domain + use-cases (no UI)
    raccpack-cli/            # binary: clap → core
    ...
```

Правило границ:

- `raccpack-core` **не** зависит от clap / ratatui / tauri / react.
- CLI зависит от core, а не наоборот.
- Вся бизнес-логика позже пойдёт только в core.

---

## 3. Входные данные / исходное состояние

- Пустой или почти пустой git-репозиторий (или новая директория).
- Нет существующих crate’ов с конфликтующими именами.
- Целевая платформа разработки: Linux (primary), Rust toolchain стабильный (актуальный stable).

## 4. Что нужно сделать (детально)

### 4.1. Корневой `Cargo.toml` (workspace)

```toml
[workspace]
resolver = "2"
members = [
    "crates/raccpack-core",
    "crates/raccpack-cli",
]
# default-members можно оставить только cli, если удобно для `cargo run`

[workspace.package]
version = "0.1.0"
edition = "2021"
license = "MIT OR Apache-2.0"   # или выбранная лицензия
authors = ["..."]
repository = "..."              # если уже есть
rust-version = "1.75"           # зафиксировать MSRV осознанно (можно скорректировать)

[workspace.dependencies]
# пока пусто или минимально; заполнять по мере надобности в следующих этапах
```

Требования:

- `resolver = "2"`.
- Версия workspace единая (`0.1.0`).
- Edition 2021 (или 2024, если команда уже на нём — зафиксировать одно).

### 4.2. Crate `raccpack-core`

Путь: `crates/raccpack-core/`

```toml
# crates/raccpack-core/Cargo.toml
[package]
name = "raccpack-core"
version.workspace = true
edition.workspace = true
license.workspace = true
description = "Core library for raccpack: scan, secrets, pack, den"
# ...

[dependencies]
# пока пусто (или только serde/thiserror позже — не в этом этапе)

[dev-dependencies]
# пусто
```

Исходники:

```text
crates/raccpack-core/
  src/
    lib.rs          # pub fn hello_core() или просто пустой модуль + //! crate docs
  Cargo.toml
  README.md         # кратко: «library, no UI»
```

`lib.rs` минимум:

```rust
//! raccpack-core — domain and use-cases. No CLI/TUI/Desktop dependencies.

/// Placeholder to keep the crate non-empty and testable.
pub fn core_version() -> &'static str {
    env!("CARGO_PKG_VERSION")
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn version_is_semver_like() {
        assert!(!core_version().is_empty());
    }
}
```

Запреты на этом этапе:

- Не добавлять `clap`, `ratatui`, `tauri`, `tokio` (если не нужен), UI-зависимости.
- Не реализовывать scan/secrets/config.

### 4.3. Crate `raccpack-cli`

Путь: `crates/raccpack-cli/`

```toml
[package]
name = "raccpack-cli"
version.workspace = true
edition.workspace = true
license.workspace = true
description = "CLI for raccpack"
# ...

[[bin]]
name = "racc"
path = "src/main.rs"

[dependencies]
raccpack-core = { path = "../raccpack-core" }
```

`src/main.rs`:

```rust
fn main() {
    println!("raccpack {}", raccpack_core::core_version());
}
```

Или ещё проще — `todo!("CLI not implemented yet")` с комментарием, что реальная реализация начнётся с M2.4 / M3.4. Главное — **компилируется** и линкуется с core.

### 4.4. Лицензия

В корне:

- `LICENSE-MIT` и/или `LICENSE-APACHE` (или один файл `LICENSE` согласно выбранной схеме).
- В `[workspace.package] license = "..."` — то же значение.
- В каждом crate `license.workspace = true`.

Рекомендация из vision: MIT OR Apache-2.0 (стандарт для Rust-экосистемы). Зафиксировать выбор явно.

### 4.5. Корневой README.md

Минимум разделов:

1. **Что это** — одно предложение из vision («сканирование проектов, секреты, очистка, упаковка в den»).
2. **Статус** — MVP / 0.1.0 in progress.
3. **Структура workspace** — дерево `crates/`.
4. **Сборка**:
   ```bash
   cargo build
   cargo test
   cargo run -p raccpack-cli
   ```
5. **Лицензия**.
6. Ссылка на roadmap / architecture (если файлы уже в `docs/`).

Не описывать несуществующие команды `racc sniff` и т.д. как уже работающие.

### 4.6. Дополнительные файлы (рекомендуется)

| Файл | Назначение |
|------|------------|
| `.gitignore` | `/target`, `Cargo.lock` (для library-centric workspace можно коммитить lock — решить явно), IDE, OS junk |
| `rust-toolchain.toml` или `rust-toolchain` | pin channel = stable (опционально) |
| `docs/` | положить (или ссылаться на) architecture-vision, roadmap |
| `CONTRIBUTING.md` | можно отложить |

`Cargo.lock`: для binary workspace обычно **коммитят**. Зафиксировать решение в README или CONTRIBUTING.

### 4.7. Проверка сборки

Обязательные команды после этапа:

```bash
cargo build --workspace
cargo test --workspace
cargo run -p raccpack-cli
```

Все должны завершаться успешно (exit 0).

## 5. Ограничения и запреты

- Не создавать `raccpack-tui`, `raccpack-tauri`, `apps/desktop-ui` на этом этапе.
- Не добавлять runtime-зависимости «на будущее» без использования.
- Не писать production-логику scan/config/secrets.
- Не менять имена crate’ов (`raccpack-core`, `raccpack-cli`) без явного решения — они зафиксированы roadmap’ом и vision.
- Binary name: `racc` (короткое имя команды).
