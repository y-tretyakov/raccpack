# M2.1 — Marker files + skip dirs → candidates

**Фаза:** M2 — Sniff (обнаружение проектов)  
**Веха:** MVP → 0.1.0  
**Статус этапа:** todo  
**Зависимости:** M1.4 (SkipPolicy + walk), M1.2 (Project path/name заготовки), M1.3 (max_depth)  
**Параллельность:** Dev + Test одновременно

---

## 1. Цель этапа

Реализовать **поиск кандидатов проектов** в дереве `scan_root`:

- обход через walk-хелпер M1.4 (`follow_links(false)`, SkipPolicy);
- распознавание **marker files / marker dirs**, которые сигнализируют «здесь корень проекта»;
- формирование списка **candidates** (пути + какие маркеры сработали);
- **без** полноценного detect языка/фреймворка (это M2.2) и **без** facade/cache/CLI.

На выходе — внутренний API, на который опираются M2.2–M2.3.

---

## 2. Контекст

Из roadmap M2.1:

> Marker files + skip dirs → candidates.

Из vision §3.1 / §4:

- scan находит проекты по markers, `.git`, wrapper-логике;
- sniff = проекты + стек + размеры (+ git summary позже).

Типичные маркеры (ориентир, не исчерпывающий список):

| Маркер | Стек-намёк |
|--------|------------|
| `Cargo.toml` | Rust |
| `package.json` | JS/TS / Node |
| `go.mod` | Go |
| `pyproject.toml`, `setup.py`, `requirements.txt` | Python |
| `pom.xml`, `build.gradle`, `build.gradle.kts` | JVM |
| `*.csproj`, `*.sln` | .NET |
| `Gemfile` | Ruby |
| `composer.json` | PHP |
| `CMakeLists.txt`, `Makefile` | C/C++ / generic |
| `.git/` (dir) | git-repo (флаг, не единственный критерий проекта) |

Правило: **директория — кандидат проекта**, если в ней есть ≥1 marker file (или marker dir в whitelist).

## 4. Типы

### 4.1. Marker

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum MarkerKind {
    /// Exact file name, e.g. "Cargo.toml"
    FileName,
    /// Exact directory name, e.g. ".git"
    DirName,
    // Extension patterns (*.csproj) — опционально в MVP; можно отложить
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct MarkerDef {
    pub kind: MarkerKind,
    /// Exact name to match on file_name() (case-sensitive on Linux).
    pub name: &'static str,
    /// Optional language hint for M2.2 (e.g. "Rust").
    pub language_hint: Option<&'static str>,
}
```

Статическая таблица:

```rust
pub static DEFAULT_MARKERS: &[MarkerDef] = &[
    MarkerDef { kind: MarkerKind::FileName, name: "Cargo.toml", language_hint: Some("Rust") },

    MarkerDef { kind: MarkerKind::FileName, name: "go.mod", language_hint: Some("Go") },
    MarkerDef { kind: MarkerKind::FileName, name: "pyproject.toml", language_hint: Some("Python") },
    MarkerDef { kind: MarkerKind::FileName, name: "setup.py", language_hint: Some("Python") },
    MarkerDef { kind: MarkerKind::FileName, name: "requirements.txt", language_hint: Some("Python") },
    MarkerDef { kind: MarkerKind::FileName, name: "pom.xml", language_hint: Some("Java") },
    MarkerDef { kind: MarkerKind::FileName, name: "build.gradle", language_hint: Some("Java") },
    MarkerDef { kind: MarkerKind::FileName, name: "build.gradle.kts", language_hint: Some("Kotlin") },
    MarkerDef { kind: MarkerKind::FileName, name: "Gemfile", language_hint: Some("Ruby") },
    MarkerDef { kind: MarkerKind::FileName, name: "composer.json", language_hint: Some("PHP") },
    MarkerDef { kind: MarkerKind::FileName, name: "CMakeLists.txt", language_hint: Some("C++") },
    MarkerDef { kind: MarkerKind::FileName, name: "Makefile", language_hint: None },
    MarkerDef { kind: MarkerKind::DirName, name: ".git", language_hint: None },

```

Минимум для MVP: Rust, Node, Go, Python, JVM (gradle/pom), `.git`. Остальное — желательно, не блокирует.

### 4.2. Candidate

```rust
use std::path::PathBuf;

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct MarkerHit {
    pub name: String,
    pub kind: MarkerKind,
    pub language_hint: Option<String>,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ProjectCandidate {
    /// Directory that contains the marker(s).
    pub path: PathBuf,
    /// Display name (usually file_name of path).
    pub name: String,
    pub markers: Vec<MarkerHit>,
    pub is_git_repo: bool, // true если среди markers есть .git dir
}
```

### 4.3. Options

```rust
#[derive(Debug, Clone)]
pub struct CandidateOptions {
    pub max_depth: usize,
    pub policy: crate::scan::SkipPolicy,
    /// Additional markers beyond DEFAULT_MARKERS (optional).
    pub extra_markers: Vec<MarkerDef>,
    /// If true, a directory with only `.git` and no other markers still becomes a candidate.
    pub accept_git_only: bool,
}

impl Default for CandidateOptions {
    fn default() -> Self {
        Self {
            max_depth: 6,
            policy: SkipPolicy::default_scan(),
            extra_markers: Vec::new(),
            accept_git_only: true,
        }
    }
}
```

## 5. Алгоритм `find_candidates`

```rust
pub fn find_candidates(
    root: &Path,
    opts: &CandidateOptions,
) -> Result<Vec<ProjectCandidate>, Error>;
```

### Шаги

1. `ensure_scan_root(root)?` (из M1.4).
2. Собрать полный список маркеров: `DEFAULT_MARKERS` + `opts.extra_markers`.
3. Walk дерева (`walk_tree` / `filter_entry` с policy, `follow_links(false)`, `max_depth`).
4. Для **каждой директории** (не файла), которую walk посетил:
   - Прочитать entries этой директории (один `read_dir`), **не** рекурсивно заново.
   - Сопоставить имена с таблицей маркеров.
   - Если есть ≥1 hit:
     - если hits только `.git` и `!accept_git_only` → skip;
     - иначе создать `ProjectCandidate`.
5. **Nested projects:** если `root/a/Cargo.toml` и `root/a/b/package.json` — оба кандидата.  
   Не схлопывать родителя автоматически (wrapper-логика — отдельное решение; MVP: все маркеры = кандидаты).
6. Сортировка результата: стабильно по `path` (для детерминированных тестов и cache keys позже).
7. Не вычислять `size_bytes` и полный `Stack` — только path/name/markers/is_git_repo.

### Производительность (ориентир)

- Один walk + `read_dir` на посещённую dir.
- Не читать содержимое файлов (только имена).
- Не следовать symlink dirs.

### Edge cases

| Ситуация | Поведение |
|----------|-----------|
| Пустой root | `Ok(vec![])` |
| Маркер в root | candidate на сам root |
| `node_modules/pkg/package.json` | не видим (skip `node_modules`) |
| Permission denied на подdir | map в `Error::Io` или skip с осторожностью; для MVP — propagate в Result всего find **или** пропускать entry (зафиксировать: **propagate** при ошибке read_dir критичного уровня; для отдельных dir — лучше skip + continue, задокументировать) |
| Dual markers в одной dir (`Cargo.toml` + `package.json`) | один candidate, несколько `MarkerHit` |

Рекомендация по ошибкам read_dir: **пропускать** недоступную dir (не ронять весь scan), но собирать не критично; для MVP достаточно «ошибка → Error», усложнять later.

## 7. Тесты (обязательные)

Fixture на tempfile:

```text
root/
  app-rust/Cargo.toml
  app-node/package.json
  app-node/node_modules/left-pad/package.json   # must NOT appear
  nested/deep/go.mod
  only-git/.git/   (simulate dir)
  empty-dir/
  target/debug/foo  # skipped via policy
```

Кейсы:

1. Находит `app-rust`, `app-node`, `nested/deep`, при `accept_git_only` — `only-git`.
2. Не находит ничего внутри `node_modules` и `target`.
3. `empty-dir` не кандидат.
4. Dual marker в одной папке → один candidate, ≥2 hits.
5. `max_depth` ограничивает `nested/deep`, если depth мал.
6. Несуществующий root → `Error::PathNotFound`.
7. Детерминированный порядок (сортировка по path).
8. Symlink на внешний проект — не входим (follow_links false).

Команда:

```bash
cargo test -p raccpack-core candidates markers
```

## 8. Ограничения и запреты

- Не определять `Stack` / frameworks — только `language_hint` на marker.
- Не считать размер проекта.
- Не писать cache.
- Не экспортировать сырые «все файлы дерева» — только candidates.
- Не менять SkipPolicy defaults без падающего теста (см. workflow).
- Case-sensitivity: на Linux exact match; не нормализовать в lower без явной политики.
