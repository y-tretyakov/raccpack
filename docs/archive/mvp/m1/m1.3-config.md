**Фаза:** M1 — Каркас workspace и core  
**Веха:** MVP → 0.1.0  
**Статус этапа:** todo

---

## 1. Цель этапа

Реализовать в `raccpack-core` **загрузку, валидацию и доступ** к конфигурации:

- формат **TOML**;
- обязательные (или default + resolve) пути: `scan_root`, `den_dir`;
- **строгие** ошибки — никаких silent defaults для критичных полей «наугад»;
- API, из которого позже соберётся `AppContext` (см. facade-документ).

Этап **не** реализует migrate chain (это Alpha A4.2), UI prompts и полный набор feature-flags секретов (частично появятся в M3 / B3).

---

## 2. Контекст

Из vision §10 и facade §2:

```text
RACCPACK_CONFIG  →  override config path
~/.config/raccpack/config.toml  →  default (XDG)

scan_root   — где лежат проекты (вход)
den_dir     — куда складывать архивы (выход)
```

`AppContext::from_config` ожидает, что `RaccConfig` умеет отдать `scan_root_dir()` и `den_dir()` как `Result`.

Инвариант: relative paths резолвятся от HOME / текущего контекста; если HOME недоступен и путь не абсолютный — **ошибка**, не «тихий cwd».

## 4. Схема конфига (MVP-минимум)

### 4.1. TOML-файл (пользовательский)

```toml
# ~/.config/raccpack/config.toml  (пример)

[paths]
scan_root = "~/DEV/PROJS"          # или абсолютный
den_dir   = "~/.raccpack/den"

# Опционально уже сейчас (с defaults):
[scanner]
max_depth = 6

# Заготовки под следующие фазы (можно не парсить строго, если #[serde(default)]):
# [sensitive]
# groups = ["env", "keys", "cloud"]
#
# [cleanup]
# enabled_strategies = ["rust", "node"]
#
# [advanced]
# parallel_jobs = 4
# zstd_level = 3
```

На M1.3 **обязательно** поддержать секцию `paths` (или плоские ключи — выбрать один стиль и зафиксировать).

Рекомендуемый стиль — **секции**, как в примере выше.

### 4.2. Rust-структура

```rust
use std::path::PathBuf;
use serde::Deserialize;

#[derive(Debug, Clone, Deserialize)]
pub struct RaccConfig {
    #[serde(default)]
    pub paths: PathsConfig,
    #[serde(default)]
    pub scanner: ScannerConfig,
    // остальные секции — #[serde(default)] пустые заготовки
}

#[derive(Debug, Clone, Deserialize)]
pub struct PathsConfig {
    /// Raw string from TOML (may contain ~).
    pub scan_root: Option<String>,
    pub den_dir: Option<String>,
}

#[derive(Debug, Clone, Deserialize)]
pub struct ScannerConfig {
    #[serde(default = "default_max_depth")]
    pub max_depth: usize,
}

fn default_max_depth() -> usize { 6 }

impl Default for PathsConfig {
    fn default() -> Self {
        Self { scan_root: None, den_dir: None }
    }
}

impl Default for ScannerConfig {
    fn default() -> Self {
        Self { max_depth: default_max_depth() }
    }
}

impl Default for RaccConfig {
    fn default() -> Self {
        Self {
            paths: PathsConfig::default(),
            scanner: ScannerConfig::default(),
        }
    }
}
```

Важно: `scan_root` / `den_dir` в TOML — **Option**, потому что могут прийти из env/CLI override. Резолв и «обязательность» — на этапе `resolve` / `validate`.

## 5. API загрузки

### 5.1. Источники (приоритет)

1. Явный путь (аргумент `load_from_path`).
2. Env `RACCPACK_CONFIG` (если задан).
3. XDG default: `$XDG_CONFIG_HOME/raccpack/config.toml` или `~/.config/raccpack/config.toml`.
4. Если файла нет — **не** ошибка: вернуть `RaccConfig::default()` **и** позволить задать пути через env/CLI позже.  
   Либо (строже): ошибка «config required» — **решить явно**. Рекомендация для MVP: файл опционален, но если файл **есть** и битый — ошибка.

### 5.2. Функции

```rust
impl RaccConfig {
    /// Load from default locations / env. Missing file → Default.
    pub fn load() -> Result<Self, ConfigError>;

    /// Load from explicit path. Missing or invalid → Error.
    pub fn load_from_path(path: &Path) -> Result<Self, ConfigError>;

    /// Resolved absolute scan root.
    pub fn scan_root_dir(&self) -> Result<PathBuf, ConfigError>;

    /// Resolved absolute den directory (may not exist yet).
    pub fn den_dir(&self) -> Result<PathBuf, ConfigError>;
}
```

Дополнительно (удобно для CLI):

```rust
/// Override paths after load (CLI flags --root / --den).
pub fn with_scan_root(mut self, path: impl Into<PathBuf>) -> Self;
pub fn with_den_dir(mut self, path: impl Into<PathBuf>) -> Self;
```

Или отдельные builder-методы — на усмотрение, но без разрастания API.

### 5.3. Резолв `~` и relative

```rust
fn expand_user_path(raw: &str) -> Result<PathBuf, ConfigError> {
    // 1. Если starts_with("~/") или "~" → подставить HOME
    // 2. Если relative → относительно current_dir() ИЛИ относительно config file dir
    //    (зафиксировать: обычно current_dir для CLI-override, config-dir для путей внутри TOML)
    // 3. canonicalize — опционально; для ещё несуществующего den_dir canonicalize может падать
}
```

Правила (зафиксировать в rustdoc):

| Ситуация | Поведение |
|----------|-----------|
| `scan_root` не задан нигде | `ConfigError::MissingScanRoot` |
| `den_dir` не задан | default `~/.raccpack/den` **или** Missing — выбрать одно. Рекомендация: default есть |
| `~` при отсутствии HOME | ошибка, не silent `/` |
| `den_dir` ещё не существует | OK (создаст raid/pack позже) |
| `scan_root` не существует | ошибка на validate / на первом sniff (решить: config validate vs runtime). Рекомендация: `scan_root_dir()` проверяет existence |

## 6. Ошибки

Предпочтительно **отдельный** `ConfigError`:

```rust
#[derive(Debug, thiserror::Error)]
pub enum ConfigError {
    #[error("config file not found: {path}")]
    FileNotFound { path: PathBuf },

    #[error("failed to read config {path}: {source}")]
    Read {
        path: PathBuf,
        #[source]
        source: std::io::Error,
    },

    #[error("invalid TOML in {path}: {source}")]
    Parse {
        path: PathBuf,
        #[source]
        source: toml::de::Error,
    },

    #[error("missing scan_root: set paths.scan_root in config or pass --root")]
    MissingScanRoot,

    #[error("cannot resolve path `{raw}`: {reason}")]
    PathResolve { raw: String, reason: String },

    #[error("scan_root does not exist: {path}")]
    ScanRootMissing { path: PathBuf },

    // …
}

impl ConfigError {
    pub fn suggestion(&self) -> Option<&'static str> { /* … */ }
}
```

## 8. Валидация (strict)

При `load` / `load_from_path` после parse:

1. TOML распарсился → структура заполнена.
2. Неизвестные ключи: serde по умолчанию **игнорирует** (deny_unknown_fields — опционально включить для строгости; для MVP можно off, чтобы не ломать будущие ключи).
3. `max_depth == 0` → ошибка или clamp? Рекомендация: ошибка `invalid max_depth`.
4. Пустые строки в `scan_root` / `den_dir` → как Missing.

Отдельный метод:

```rust
impl RaccConfig {
    pub fn validate(&self) -> Result<(), ConfigError>;
}
```

Вызывать из `load*` после deserialize.

## 9. Тесты (обязательные)

1. **Default** — `RaccConfig::default()` не паникует; `den_dir()` резолвится в ожидаемый default path (с mock HOME).
2. **Parse minimal TOML** из строки / tempfile.
3. **Missing file** на `load_from_path` → `FileNotFound`.
4. **Invalid TOML** → `Parse`.
5. **`~` expansion** при заданном `HOME` в env (test-only).
6. **Missing scan_root** → `MissingScanRoot` при вызове `scan_root_dir()`.
7. **Relative path** резолвится предсказуемо.
8. **max_depth** default == 6.
9. Нет raw panic на пустом файле / пустых paths.

Использовать `tempfile`, `std::env::set_var` осторожно (serial tests или `temp-env` crate). Для HOME — `serial_test` или изоляция.

Команда:

```bash
cargo test -p raccpack-core config
```
