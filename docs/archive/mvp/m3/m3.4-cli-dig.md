## 3. Clap-интерфейс

Расширить `Commands` из M2.4:

```text
racc dig [OPTIONS]

Options:
      --root <PATH>         Scan root (or use config / global --root)
      --project <PATH>      Limit dig to one project directory
      --json                JSON output (Sniff-style: full DigResult)
      --no-content          Disable content scan (filename only)
      --repeated            Find repeated secrets across files
      --fail-on <POLICY>    ignore | critical | high   (default: critical)
      --max-depth <N>       Override max depth (if dig respects it via context)
```

Маппинг policy:

| CLI value | SecretExitPolicy |
|-----------|------------------|
| `ignore` | Ignore |
| `critical` | FailOnCritical |
| `high` | FailOnHighOrAbove |

Default: **`critical`** (FailOnCritical).

Глобальные `--config`, `--root`, `--json` наследуются.

---

## 4. Поток `run_dig`

```text
1. Load config + overrides (как sniff)
2. AppContext::from_config(..., RunMode::DryRun)
3. Apply exit_policy from --fail-on into ctx (or local variable)
4. DigOptions {
     project: cli.project,
     find_repeated: cli.repeated,
     scan_content: !cli.no_content,
     use_heuristics: None,
   }
5. progress = NullProgress or simple spinner if not json
6. result = dig(&ctx, &opts, &mut progress)?
7. if json → print DigResult as pretty JSON
   else → print_human_dig(&result)
8. code = exit_code_for_secrets(&result.files, policy)
9. if code != 0 && !json:
       eprintln!("Sensitive findings triggered exit policy ({policy})");
10. exit(code)  // 0 or 2; IO errors already returned as exit 1 before
```

IO/config errors → exit **1**.  
Policy trigger → exit **2**.  
Success without policy fail → **0**.

## 5. Human output (пример)

```text
Dig root: /home/user/DEV/PROJS
Files scanned: 1204  |  Findings: 5  |  Repeated: 1  |  180 ms

RISK       LABEL              PATH
Critical   AWS Access Key     /…/app/config/aws.env
Critical   Private key PEM    /…/app/certs/server.key
High       Env file           /…/app/.env
High       npmrc              /…/web/.npmrc
Medium     JWT-like           /…/scripts/token.txt

Repeated secrets:
  hash=ab12…  risk=High  count=2
    /…/app/.env
    /…/app/.env.backup

Exit policy: fail on critical → exit 2
```

Требования:

- сортировка: risk desc, затем path;
- masked preview можно одной колонкой (коротко);
- **не** печатать raw;
- size/duration/files_scanned для UX.

JSON: полный `DigResult` serde.

## 6. Тесты

1. clap parse dig flags.
2. Integration: fixture with `.env` → exit 0 or 2 depending on policy; with Critical content → exit 2 if `--fail-on critical`.
3. `--json` → valid JSON, no raw from fixture password.
4. `--no-content` → filename-only findings.
5. `--fail-on ignore` → exit 0 even with Critical.
6. Missing root → exit 1.

```bash
cargo test -p raccpack-cli
```

Ручной E2E:

```bash
cargo run -p raccpack-cli -- dig --root FIXTURE
cargo run -p raccpack-cli -- dig --root FIXTURE --json | jq .
cargo run -p raccpack-cli -- dig --root FIXTURE --fail-on ignore; echo $?
```
