# M3.3 — Facade `dig` (masked output, без raw в report)

**Фаза:** M3 — Dig (секреты, read-only)  
**Веха:** MVP → 0.1.0  
**Статус этапа:** todo  
**Зависимости:** M3.1, M3.2, M2.3 (AppContext, ProgressSink patterns), M1.2  
**Параллельность:** Dev + Test одновременно

---

## 1. Цель этапа

Собрать **публичный use-case `dig`**:

- вход: `AppContext` + `DigOptions` + `ProgressSink`;
- выход: `DigResult` с `SensitiveFile[]` и опционально `RepeatedSecret[]`;
- **только masked** данные, без raw secrets;
- progress phase `"dig"`;
- helper `exit_code_for_secrets` для CLI.

Read-only: никаких записей на диск, никаких stash/delete.

## 3. Public DTO

### 3.1. `SensitiveFile`

```rust
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct SensitiveFile {
    pub path: PathBuf,
    pub risk: SensitiveRisk,
    /// Filename and/or content labels
    pub labels: Vec<String>,
    /// Optional masked content preview (if content hit)
    pub content_match: Option<MaskedValue>,

}
```

Имена полей можно слегка уточнить, но смысл: path + risk + masked only.

### 3.2. `RepeatedSecret`

```rust
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct RepeatedSecret {
    pub value_hash: String,
    pub masked: String,
    pub risk: SensitiveRisk,  // max across occurrences
    pub paths: Vec<PathBuf>,
    pub count: usize,
}
```

Только если `find_repeated: true` и есть hash, встречающийся в ≥2 files.

### 3.3. Re-exports

В `lib.rs` / `domain` / `report` — публичные DTO для JSON CLI.

## 4. Алгоритм `dig`

```text
1. t0 = Instant::now()
2. root = opts.project.clone().unwrap_or_else(|| ctx.paths.scan_root.clone())
3. ensure_scan_root(&root)?  // or ensure path is under scan_root if project set
4. progress.emit(dig, 0%, "starting")
5. Build SecretScanOptions from ctx + opts:
     max_depth from config
     policy default_scan
     min_risk Low (or config later)
     scan_content = opts.scan_content
     limits default
     find_repeated = opts.find_repeated
6. findings = scan_secrets(&root, &secret_opts)?
7. files_scanned = … (track during scan; add counter to scan API if needed)
8. progress.emit(… "aggregating")
9. files = findings → Vec<SensitiveFile> (map labels, content_match)
10. repeated = if opts.find_repeated { aggregate_by_hash(&findings) } else { vec![] }
11. progress.emit(100%, phase_complete)
12. Ok(DigResult { root, files, repeated, duration_ms, files_scanned })
```

### Path containment

Если `opts.project` задан:

- path должен существовать;
- желательно: `project` находится **под** `ctx.paths.scan_root` (или равен). Если нет — Error или warning; **рекомендация:** разрешить абсолютный project path (CLI dig one repo), без жёсткой привязки к scan_root.

### Groups override

`ctx.secret_groups_override` — на MVP можно игнорировать (все markers on). Включить фильтры groups в B3.

### Heuristics

`use_heuristics: None` → default off/on из config; если не реализовано — ignore без ошибки.

## 5. `exit_code_for_secrets`

```rust
pub fn exit_code_for_secrets(files: &[SensitiveFile], policy: SecretExitPolicy) -> i32 {
    match policy {
        SecretExitPolicy::Ignore => 0,
        SecretExitPolicy::FailOnCritical => {
            if files.iter().any(|f| f.risk == SensitiveRisk::Critical) { 2 } else { 0 }
        }
        SecretExitPolicy::FailOnHighOrAbove => {
            if files.iter().any(|f| f.risk >= SensitiveRisk::High) { 2 } else { 0 }
        }
    }
}
```

Только 0 или 2; IO-ошибки — exit 1 на уровне CLI, не здесь.

## 7. Тесты (обязательные)

1. Fixture: `.env` + file with `AKIA…` → ≥1 SensitiveFile, risk correct, `content_match` masked.
2. JSON serialize DigResult — **no** raw secret substrings from fixture in output string.
3. `find_repeated: true` — two files same password → one RepeatedSecret count=2.
4. `scan_content: false` — only filename hits.
5. `project: Some(subdir)` — findings only under subdir.
6. Empty tree → files empty, exit_code 0 for any policy.
7. Critical present → `exit_code_for_secrets(..., FailOnCritical) == 2`.
8. Progress sink receives phase_complete.
9. SkipPolicy respected.

Команда:

```bash
cargo test -p raccpack-core dig
```

## 8. Ограничения и запреты

- dig **read-only**.
- Нет raw в `DigResult` / `SensitiveFile` / `RepeatedSecret`.
- Нет записи cache dig в MVP (опционально later).
- Не вызывать age/stash.
- Не менять exit codes внутри dig (только helper).
