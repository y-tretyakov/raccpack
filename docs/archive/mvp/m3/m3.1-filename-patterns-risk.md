## 4. Filename patterns

### 4.1. Структура правила

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum NameMatchKind {
    /// Exact file name: ".env"
    Exact,
    /// Suffix: ends with ".pem"
    Suffix,
    /// Prefix: starts with "id_rsa"
    Prefix,
    /// Contains substring (use sparingly): "secret"
    Contains,
    /// Glob-like simple: "*.pem" implemented as suffix ".pem" after stripping *
    // Prefer explicit kinds over full glob engine in MVP
}

#[derive(Debug, Clone)]
pub struct FilenamePattern {
    pub kind: NameMatchKind,
    pub pattern: &'static str,
    pub risk: SensitiveRisk,
    /// Stable id for tests/docs (e.g. "env_file", "private_key")
    pub id: &'static str,
    /// Human label for reports
    pub label: &'static str,
}
```

**Важно:** таблица — data-driven (`static` slice). Порядок: при нескольких match на один файл берётся **максимальный risk** (severity upgrade).

False positives (`.key` на не-секретных файлах) допустимы на High; Critical — только для более однозначных имён.

### 4.3. Matching API

```rust
use std::path::Path;

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct FilenameMatch {
    pub pattern_id: String,
    pub label: String,
    pub risk: SensitiveRisk,
}

/// Match a single file path (uses file_name only).
pub fn match_filename(path: &Path) -> Option<FilenameMatch>;

/// Highest-risk match if several patterns hit.
pub fn match_filename_all(path: &Path) -> Vec<FilenameMatch>;
```

Правила:

- сравнение на `path.file_name()` lossy string;
- Linux: case-sensitive; не lower-case весь мир без политики;
- directories **не** матчить как filename secrets (только files), кроме явных dir-маркеров если добавите позже.

### 4.4. Scan filenames in tree

```rust
#[derive(Debug, Clone)]
pub struct FilenameScanOptions {
    pub max_depth: usize,
    pub policy: crate::scan::SkipPolicy,
    /// Minimum risk to include (default: Low = all).
    pub min_risk: SensitiveRisk,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct SensitiveFinding {
    pub path: PathBuf,
    pub risk: SensitiveRisk,
    pub source: FindingSource,
    pub label: String,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum FindingSource {
    Filename { pattern_id: String },
    // Content { .. } — M3.2
}

pub fn scan_filenames(
    root: &Path,
    opts: &FilenameScanOptions,
) -> Result<Vec<SensitiveFinding>, Error>;
```

Алгоритм:

1. `ensure_scan_root(root)?`
2. Walk с `follow_links(false)`, SkipPolicy, max_depth.
3. Для каждого **file** entry → `match_filename`.
4. Если risk ≥ min_risk → push finding.
5. Сортировка: по path, затем risk desc — детерминизм.

Не читать file content.

## 5. Severity API (risk model)

`SensitiveRisk` уже `Ord`. Зафиксировать helpers:

```rust
impl SensitiveRisk {
    pub fn at_least(self, min: Self) -> bool {
        self >= min
    }
}

/// Merge two risks → max.
pub fn upgrade_risk(a: SensitiveRisk, b: SensitiveRisk) -> SensitiveRisk {
    a.max(b)
}
```

Правила (документировать):

1. Filename match задаёт **базовый** risk.
2. Content match (M3.2) может **upgrade** risk того же path, не downgrade.
3. Несколько filename patterns → max risk.
4. Нет silent default Critical.

Запрет из workflow FINAL:

> SensitiveRisk upgrade только через severity API.

## 7. Тесты (обязательные)

1. `.env` → High, pattern_id `env_file`.
2. `id_rsa` → Critical.
3. `notes.txt` → None.
4. `foo.pem` → High (suffix).
5. Dual pattern → max risk.
6. `scan_filenames` на fixture: находит `.env`, не заходит в `node_modules/.env`.
7. `min_risk: Critical` отфильтровывает High.
8. Ordering `Low < Medium < High < Critical`.
9. `upgrade_risk(High, Critical) == Critical`.
10. Детерминированный порядок findings.

Команда:

```bash
cargo test -p raccpack-core filename risk secrets
```
