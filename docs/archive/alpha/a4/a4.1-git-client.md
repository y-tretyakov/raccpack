# A4.1 — GitClient (process) + status sensitive files в dig

**Фаза:** A4 — Git и DX alpha  
**Зависимости:** M3.3 dig (`SensitiveFile.git_status`), M1.2 Error  
**Параллельность:** Dev + Test

---

## 1. Цель

1. Trait **`GitClient`** + реализация через **subprocess `git`** (не libgit2 обязательно в Alpha).
2. Для каждого finding в dig: заполнить `git_status` (tracked / untracked / ignored / modified / …).
3. Mock для тестов без реального git.
4. Если `git` нет или path не repo — status `None` / `"unavailable"`, dig **не** падает.

## 3. API

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum GitFileStatus {
    Tracked,
    Untracked,
    Ignored,
    Modified,
    Staged,
    Deleted,
    Unknown,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct GitState {
    pub is_repo: bool,
    pub dirty: bool,
    // branch optional later
}

pub trait GitClient: Send + Sync {
    fn is_repo(&self, path: &Path) -> Result<bool, Error>;
    fn file_status(&self, repo: &Path, file: &Path) -> Result<GitFileStatus, Error>;
    /// Batch preferred for dig performance
    fn files_status(
        &self,
        repo: &Path,
        files: &[PathBuf],
    ) -> Result<HashMap<PathBuf, GitFileStatus>, Error>;
}

pub struct ProcessGitClient {
    pub git_binary: PathBuf, // default "git"
    pub timeout: Duration,   // default 30s
}
```

### 3.1. Process implementation

Commands (illustrative):

```bash
git -C <repo> rev-parse --is-inside-work-tree
git -C <repo> status --porcelain=v1 --ignored=matching -- <files…>
```

Map porcelain prefixes:

| Prefix | Status |
|--------|--------|
| `??` | Untracked |
| `!!` | Ignored |
| ` M` / `M ` / `MM` | Modified |
| `A ` / `AM` | Staged (or Tracked+Staged) |
| ` D` / `D ` | Deleted |
| `  ` (tracked clean) | Tracked |

Не требовать network. `GIT_TERMINAL_PROMPT=0`.

### 3.2. Dig integration

```text
after scan_secrets → list paths
find repo root: walk up for .git from dig root / project
if is_repo:
  statuses = git.files_status(repo, paths)
  for each SensitiveFile: git_status = Some(format/status)
else:
  git_status = None
```

Serialize as string in JSON for stability: `"modified"`, `"ignored"`, … (serde on enum).

## 4. Тесты

1. MockGitClient returns programmed map → dig fills git_status.
2. Non-repo path → all None, dig Ok.
3. ProcessGitClient: tempfile `git init` + add file + `.env` untracked → Untracked (integration `#[ignore]` if no git in CI optional, or require git in CI).
4. Ignored via `.gitignore` → Ignored.
5. Timeout / missing git binary → soft fail (None), not dig Err.

```bash
cargo test -p raccpack-core git
```

## 5. CLI impact (примеры)

Git status виден в dig output — отдельные флаги git в A4.1 **не** обязательны.

```bash
# dig покажет колонку/поле git status для findings
racc dig --project ~/DEV/PROJS/my-api
racc dig --project ~/DEV/PROJS/my-api --json | jq '.files[] | {path, risk, git_status}'

# sniff может позже показать is_git_repo (уже с M2 candidates)
racc sniff --root ~/DEV/PROJS --json | jq '.report.projects[] | {name, is_git_repo}'
```
