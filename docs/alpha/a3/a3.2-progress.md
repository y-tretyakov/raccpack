# A3.2 — ProgressSink + CLI progress для raid

**Фаза:** A3 — Raid orchestration  
**Зависимости:** A3.1 (raid phases), existing ProgressEvent types  
**Параллельность:** Dev + Test (можно с A3.1)

---

## 1. Цель

1. Единые **progress events** на уровне raid (не только вложенные stash/rinse/pack).
2. CLI: понятный progress при `racc raid` (spinner / phase lines) без `--json`.
3. `phase_count` / `phase_index` / `overall_percent` согласованы с числом enabled фаз + move.

---

## 3. Контракт ProgressEvent (напоминание)

```rust
pub struct ProgressEvent {
    pub operation: OperationKind, // Raid
    pub phase: String,            // "stash" | "rinse" | "pack" | "move" | "scan"
    pub phase_index: u32,         // 0-based among planned phases
    pub phase_count: u32,
    pub percent: u8,              // within phase 0..=100
    pub overall_percent: u8,      // 0..=100
    pub message: String,          // human, no raw secrets
    pub phase_complete: bool,
}
```

### 3.1. Планирование phase_count

```text
planned = []
if stash.enabled { planned.push("stash") }
if rinse.enabled { planned.push("rinse") }
if pack.enabled  { planned.push("pack") }
planned.push("move")   // always last logical step when orchestration runs
phase_count = planned.len()
```

При fail-fast последующие фазы не emit'ят complete success; можно emit skip message.

### 3.2. Overall percent (простая формула)

```text
overall = ((phase_index * 100) + phase_percent) / phase_count
```

clamp 0..=100.

## 4. CLI progress UX

Без `--json`:

```text
Raid [1/4] stash   ################----  80%  Encrypting…
Raid [2/4] rinse   done (2 dirs, 140 MiB)
Raid [3/4] pack    ##########----------  50%  Archiving…
Raid [4/4] move    done
Raid complete — success=true
```

Или проще (MVP CLI):

```text
→ stash: archived 3 files
→ rinse: removed 2 dirs (140 MiB)
→ pack: wrote 12 MiB
→ move: finalized
Success
```

Не использовать ANSI-обязательность; plain text OK.

С `--json`: **NullProgress** (или тихий sink), в stdout только финальный `RaidResult`.

---

## 5. Тесты

1. Test sink collects events; last has overall 100 and phase_complete on final phase.
2. phase_count == number enabled + 1 (move).
3. Disabled stash → no phase name "stash" in successful emits (or only skipped with skipped semantics — согласовать с A3.1 stages).
4. Messages do not contain fixture secret raw values.
5. CLI smoke: not required to parse ANSI; ensure no panic with CliProgress.

```bash
cargo test -p raccpack-core progress raid
cargo test -p raccpack-cli raid
```
