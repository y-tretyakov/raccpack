# A3.3 — Atomic upgrade поверх shipped fail-fast raid

**Статус:** NEXT (первый незакрытый этап Alpha)  
**База:** A3.1 + A3.2 в `dev`  
**Цель vision:** default **Atomic**; FailFast только `--fail-fast` / `OrchestrationMode::FailFast`

---

## 1. Проблема сейчас

При `success: false` после stash/pack уже могут лежать `.age` / `.tar.zst` в den — **orphan**.  
Alpha exit требует: ошибка → исходное состояние, нет orphan.

---

## 2. Цель этапа

1. `OrchestrationMode { Atomic, FailFast }` в `RaidOptions` (default **Atomic**).  
2. Весь Commit-raid в `den/staging/{raid_id}/` + **WAL** до side effects.  
3. Финальные `secrets/` / `packs/` только atomic **rename** в commit.  
4. `Err` → reverse WAL → `rolled_back: true`, staging removed.  
5. FailFast сохраняет **текущее** поведение A3.1 (для debug / `--fail-fast`).  
6. DryRun: без WAL, без FS (как сейчас).  
7. Progress: фазы `commit` / `rollback` при необходимости.  
8. Регрессия: существующие `--test raid` / `raid_progress` зелёные; новые orphan-тесты.

---

## 3. Policy destructive ops (обязательно зафиксировать в коде + rustdoc)

Чтобы rollback был реализуем без «восстановления node_modules»:

| Операция | Когда в Atomic |
|----------|----------------|
| Encrypt → staging `.age` | mid-raid OK |
| Pack → staging `.tar.zst` | mid-raid OK |
| `remove_sources` | **только в commit** после successful rename secrets |
| `rinse` delete | **только в commit** (или сразу после pack в staging, до den rename — предпочтительно **commit**) |

FailFast может оставить прежний порядок A3.1 (rinse mid-pipeline) — документировать.

---

## 4. Модульность

```text
app/raid/
  mod.rs          # mode branch: atomic_raid vs fail_fast_raid (текущий поток)
  staging.rs      # create_raid_staging / remove
  wal.rs          # WalOp JSONL, append+fsync, iter_reverse
  rollback.rs     # apply reverse + report
  stages.rs       # existing
  progress.rs     # add commit/rollback phase names
```

Не раздувать `mod.rs` > 400 — выносить runners.

## 6. WAL ops (минимум)

```rust
enum WalOp {
    CreateFile { path: PathBuf },
    Rename { from: PathBuf, to: PathBuf },
    DeleteFile { path: PathBuf },
    DeleteDir { path: PathBuf },
}
```

Правило: `append + fsync` **до** эффекта.

## 7. Orphan regression (из vision A3.0)

| ID | Сценарий | Atomic ожидание |
|----|----------|-----------------|
| ORPHAN-1 | pack fails after staging secrets | нет файла в den/secrets; staging пуст |
| ORPHAN-2 | rename fails mid-commit | den consistent; rollback |
| ORPHAN-3 | DryRun | zero WAL/FS |
| ORPHAN-4 | FailFast + pack fail | **может** orphan (документировано) |

Fault injection: test-only hook or mock pack error after staging write.
