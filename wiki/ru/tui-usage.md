# TUI (терминальный интерфейс)

::: info
TUI строится в Beta (0.5.x). По состоянию на **0.4.4** работают **экраны sniff, dig и raid** (таблица проектов, неблокирующий worker, находки секретов с маскированными деталями), плюс визуальный стиль (тема + shell); reveal-модалка планируется.
:::

## Что это

`racc-tui` — интерактивный терминальный интерфейс на базе Ratatui. Позволяет работать с проектами и секретами без запоминания команд: навигация, таблица проектов, подтверждения.

## Shell

- **Sidebar**: бренд `◈ RACCPACK` + корень workspace, навигация, живые бейджи — `Projects` показывает реальное число отсканированных проектов, `Findings` считает находки последнего dig (янтарный, если > 0; muted при 0; `·` до первого dig). Внизу — версия приложения.
- **Header**: бренд, корень сканирования и версия; подсказки клавиш справа (на узких терминалах сворачиваются).
- **Footer**: счётчики состояния.

## Экран sniff (доступен с 0.4.2)

- Выводит проекты из корня сканирования в таблице: имя, язык, фреймворки, размер, признак git-репозитория.
- Запускает `sniff` в фоновом worker-потоке, поэтому UI остаётся отзывчивым (показывается индикатор прогресса) во время сканирования.
- Навигация: `j`/`k` (или стрелки) — выбор строки; `r` — обновить; `o` — смена корня сканирования (зарезервирована, ещё не реализована); `Enter` — открыть проект (dig, с 0.4.3).

## Экран dig (доступен с 0.4.3)

- Открывается по `Enter` на проекте в экране sniff и запускает скан секретов в фоновом worker-потоке.
- Таблица находок: риск, путь, вид, git-статус — **только маскированные значения**, никогда raw.
- Фильтр по минимальному риску: `f` циклирует all → critical → high+ → medium+.
- `c` переключает content-скан (повторный dig с/без значений в содержимом); `r` — повторный dig; `Esc` — возврат в экран sniff.
- Под таблицей — полоса деталей выбранной находки; навигация `j`/`k`, первая/последняя `g`/`G`.

## Raid-flow (доступен с 0.4.4)

- Нажмите `R` на выбранном проекте в экране sniff — мастер raid откроется модальным оверлеем.
- Сначала показывается **preview**: проект, бейдж режима (`ATOMIC` / `FAIL-FAST`), фазы, которые выполнятся (stash → rinse → pack), и пометка dry-run — **пока ничего не пишется**.
- Подтверждение — `y` (или `Enter`), отмена — `n`/`Esc`. Переключатели: `K` keep sources, `S` skip stash, `m` режим.
- Если stash включён — **модалка passphrase** собирает его дважды (`•` вместо символов); переменная `RACCPACK_PASSPHRASE` пропускает запрос. Passphrase не попадает в состояние TUI, логи или debug-вывод.
- Во время **выполнения** модалка показывает пайплайн фаз (`✓` готова, `→` текущая, `○` ожидает), общий прогресс-бар и сообщение фазы — всё из реальных событий ядра. `Esc` не отменяет запущенный raid (у ядра нет cancel).
- **Результат** честный: success, rolled back (с количеством rollback-предупреждений) или failed; в режиме `FAIL-FAST` выводится предупреждение, что уже размещённые артефакты могут остаться. Размещённые артефакты перечислены относительно den. `Enter`/`Esc` закрывает.

## Целевые возможности

- **Подтверждение raid** — готово (с 0.4.4): мастер с прогрессом по фазам и честным результатом (см. выше).
- **Dry-run** — встроен в мастер raid: preview никогда ничего не пишет в den.
- **Reveal-модалка** — безопасный opt-in показ маскированного/короткого значения секрета (планируется, B1.5).

## Как это будет работать

TUI использует тот же публичный контракт ядра, что и CLI, поэтому результаты и политики (риски, маскирование, dry-run) одинаковы во всех интерфейсах.

```
нажатие клавиши  →  состояние экрана TUI  →  вызов facade
                 ←  события прогресса + отчёт ←  ядро
                 →  обновление панелей
```

## Прогресс длинных операций

Длинные операции (глубокий `dig`, полный `raid`) шлют события прогресса: фаза, процент, сообщение. TUI перерисовывает экран по каждому событию, не блокируя интерфейс.

## Визуальная система (design tokens)

Цветовая семантика TUI задаётся design-токенами в формате **DTCG** (`docs/design-tokens/raccpack.tokens.json`) — единый источник и для TUI, и для будущего Desktop. Текущая палитра — **графит + оранж** (бренд/фокус оранжевый; teal больше не используется) через маппинг primitive → semantic. Экран использует semantic-имена (`bg`, `fg`, `accent`, `muted`, `danger`, `selection` и т.д.), а размеры (ширина сайдбара, высота панелей) — в **терминальных клетках**. Это значит, что «перекрасить» продукт можно правкой одного файла, не трогая виджеты.
